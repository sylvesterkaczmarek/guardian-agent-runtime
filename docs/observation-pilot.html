GUARDIAN AGENT RUNTIME / RESEARCH NOTE 0.5.0

What a tool acknowledgement can establish

Sylvester Kaczmarek · 21 November 2026

A worker can acknowledge a write and leave the destination untouched. It can also write the requested value and then return an error. An agent that equates acknowledgement with completion will get both cases wrong. This pilot asks which claims an evaluator can decide when given a tool response, a final observation or a record of each committed state.

Two tools and three claims

A joint simulator moved towards position 3. A subprocess file worker committed the integer 4 to a disposable file. Each workflow used a parent request and two separately authorised child operations. For the file worker, a reader in the parent process reopened the destination between synchronised updates. The evaluation retained the full discrete history as ground truth. Each checker received only its assigned view.

The three claims concerned (1) whether the final value equalled the target, (2) whether it was within the inclusive range 0 to 5, and (3) whether every committed value stayed in that range. For example, a trajectory of 0, 7, 4 satisfies the file goal and endpoint bound but violates the trajectory bound. A reader that sees only the final 4 can establish the first two claims. The third remains unknown.

Frozen predictions

Seven conditions per tool covered normal completion, acknowledged no-op, committed change followed by error, temporary excursion, wrong final value, missing observations and delayed observations. Each condition was evaluated through three views. With two tools and three claims per view, the pilot yielded 126 claim decisions across 42 executions.

Evidence Predicted scope of a verdict
Acknowledgement alone Provides the reported status. All three state claims remain unknown.
Fresh terminal sample Decides both final-state claims. A value outside the bound also refutes the trajectory claim.
Complete transition history Decides all three claims within the discrete observation model.
Stale or partial observations An observed breach refutes the trajectory claim. A missing final sample leaves final-state claims unknown.

OBSERVED OUTCOMES / RESULTS

The same observations yielded the same verdicts

The acknowledgement baseline treated tool success as completion and abstained on the range claims. The simple checker and Guardian interpreted identical recorded samples. Guardian additionally verified the signed evidence and linked the observed child operation to its authorised parent.

Across both tools Ack. baseline Simple checker Guardian
Correct on 52 predicted-answerable claims 8 52 52
False confirmations 12 0 0
False denials 6 0 0
Unknown verdicts (out of 126) 84 74 74
Actual violations missed (out of 30) 30 12 12

Guardian and the simple checker agreed on every verdict. Twelve of their 74 unknowns were actual violations. An unknown verdict therefore cannot be counted as a safe outcome. Both admission systems also refused the out-of-range and unavailable-state controls before the tool ran.

What the pilot supports

The frozen protocol predicted when the available observations would settle a claim. Signed records gave a separate verifier a way to authenticate the recorded observations and their association with a particular authorised operation. Greater verdict accuracy over the equal-information checker would require additional evidence. The prespecified superiority criterion was unmet.

There was one implementation per backend. Repeated views and claims from a single implementation are dependent. These counts cannot establish performance on other tools or a population-level error rate. The study covers discrete transitions and a trusted observer. A signature establishes who attested to a reading. Sensor accuracy, continuous physical motion and crash durability require separate tests.

Reproduce the result

Use Python 3.12 or later in a fresh environment. Run the following commands, then compare pilot/report.json with the case-level results in the release.

python -m pip install guardian-runtime-assurance==0.5.0
guardian-study --output pilot

The output includes a manifest, example public key and signed evidence bundle per backend. The example keys are public fixtures. Use the verification commands, frozen protocol and case-level results to inspect any verdict.
